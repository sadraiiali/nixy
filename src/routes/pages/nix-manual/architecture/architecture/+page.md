# 9. معماری و طراحی

این فصل به تشریح نحوه کارکرد Nix می‌پردازد.
این بخش باید به کاربران کمک کند تا درک کنند چرا Nix به این شکل رفتار می‌کند، و همچنین باید به توسعه‌دهندگان کمک کند تا بفهمند چگونه Nix را تغییر دهند و ابزارهای مشابهی بنویسند.

## نمای کلی

Nix از [لایه‌های سلسله‌مراتبی] تشکیل شده است.

[hierarchical layers]: https://en.wikipedia.org/wiki/Multitier_architecture#Layers

[نقشه مفهومی] زیر اجزای اصلی آن (مستطیل‌ها)، اشیایی که روی آن‌ها کار می‌کنند (مستطیل‌های گرد)، و تعاملات آن‌ها (عبارات اتصال‌دهنده) را نشان می‌دهد:

[concept map]: https://en.wikipedia.org/wiki/Concept_map

```

   .----------------.
   | Nix expression |----------.
   '----------------'          |
           |              passed to
           |                   |
+----------|-------------------|--------------------------------+

|          |       | command line interface |------.            |
```

در بالاترین بخش، [رابط خط فرمان](/pages/nix-manual/command-ref) قرار دارد که لایه‌های زیرین را هدایت می‌کند.

ارزیاب [زبان Nix](/pages/nix-manual/language)، عبارت‌های Nix را به *طرح‌های ساخت (build plans)* مستقل تبدیل می‌کند که از آن‌ها برای استخراج *نتایج ساخت (build results)* از *ورودی‌های ساخت (build inputs)* ارجاع‌شده استفاده می‌شود.

رابط خط فرمان و عبارت‌های Nix مواردی هستند که کاربران بیشترین سر و کار را با آن‌ها دارند.

> **نکته**
>
> خود زبان Nix هیچ مفهومی از *بسته‌ها* یا *پیکربندی‌ها* ندارد.
> تا آنجا که در اینجا مد نظر ماست، ورودی‌ها و نتایج یک طرح ساخت صرفاً داده هستند.

در زیرِ رابط خط فرمان و ارزیاب زبان Nix، [انبار Nix](/pages/nix-manual/store) قرار دارد؛ مکانیزمی برای پیگیری طرح‌های ساخت، داده‌ها و ارجاعات میان آن‌ها.
این انبار همچنین می‌تواند طرح‌های ساخت را برای تولید داده‌های جدید اجرا کند که به عنوان فایل‌ها در دسترس سیستم‌عامل قرار می‌گیرند.

خودِ یک طرح ساخت، مجموعه‌ای از *وظایف ساخت (build tasks)* به همراه ورودی‌های ساخت آن‌هاست.

> **مهم**
> یک وظیفه ساخت در Nix [درایویشن انبار](/pages/nix-manual/glossary#gloss-store-derivation) نامیده می‌شود.

هر وظیفه ساخت دارای یک ورودی ساخت خاص است که به عنوان *دستورالعمل‌های ساخت (build instructions)* برای انجام عملیات ساخت اجرا می‌شود.
نتیجه یک وظیفه ساخت می‌تواند به عنوان ورودی برای وظیفه ساخت دیگری استفاده شود.

[نمودار جریان داده] زیر برای نمونه، یک طرح ساخت را نشان می‌دهد.
ورودی‌های ساختی که به عنوان دستورالعمل برای یک وظیفه ساخت استفاده می‌شوند، بر همین اساس مشخص شده‌اند:

[نمودار جریان داده]: https://en.wikipedia.org/wiki/Data-flow_diagram

```
+--------------------------------------------------------------------+
| build plan                                                         |
|                                                                    |
| .-------------.                                                    |
| | build input |---------.                                          |
| '-------------'         |                                          |
|                    instructions                                    |
|                         |                                          |
|                         v                                          |
| .-------------.    .----------.                                    |
| | build input |-->( build task )-------.                           |
| '-------------'    '----------'        |                           |
|                                  instructions                      |
|                                        |                           |
|                                        v                           |
| .-------------.                  .----------.     .--------------. |
| | build input |---------.       ( build task )--->| build result | |
| '-------------'         |        '----------'     '--------------' |
|                    instructions        ^                           |
|                         |              |                           |
|                         v              |                           |
| .-------------.    .----------.        |                           |
| | build input |-->( build task )-------'                           |
| '-------------'    '----------'                                    |
|                         ^                                          |
|                         |                                          |
|                         |                                          |
| .-------------.         |                                          |
| | build input |---------'                                          |
| '-------------'                                                    |
|                                                                    |
+--------------------------------------------------------------------+
```
