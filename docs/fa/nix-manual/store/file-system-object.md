# شیء سیستم‌فایل

نیکس از مدل ساده‌سازی‌شده‌ای از سیستم‌فایل استفاده می‌کند که از اشیاء سیستم‌فایل تشکیل شده‌است.
هر شیء سیستم‌فایل یکی از موارد زیر است:

 - [**پروندهٔ معمولی**]{#regular}

   - یک دنباله از بایت‌ها برای محتوا که ممکن است خالی باشد
   - یک مقدار بولین منفرد که نشان‌دهندهٔ مجوز [اجرا](https://en.m.wikipedia.org/wiki/File-system_permissions#Permissions) است

 - [**پوشه**]{#directory}

   نگاشتی از نام‌ها به اشیاء سیستم‌فایل فرزند

 - [**پیوند نمادین**]{#symlink}

   یک رشتهٔ دلخواه که به عنوان *هدف* پیوند نمادین شناخته می‌شود.

   به طور کلی، نیکس هیچ معناشناسی خاصی را به پیوندهای نمادین اختصاص نمی‌دهد.
   با این حال، برخی عملیات ممکن است فرض‌های اضافی در نظر بگیرند و تلاش کنند از هدف برای یافتن شیء سیستم‌فایل دیگری استفاده کنند.

   > اگر با این مفهوم یونیکس آشنایی ندارید، برای کسب اطلاعات پس‌زمینه به [مقالهٔ ویکی‌پدیا دربارهٔ پیوندهای نمادین](https://en.m.wikipedia.org/wiki/Symbolic_link) مراجعه کنید.

اشیاء سیستم‌فایل و فرزندان آن‌ها یک درخت را تشکیل می‌دهند.
یک پروندهٔ ساده یا پیوند نمادین می‌تواند به عنوان یک شیء سیستم‌فایل ریشه عمل کند.

نیکس هیچ‌گونه مفهوم دیگری از سیستم‌فایل مانند [پیوندهای سخت](https://en.m.wikipedia.org/wiki/Hard_link)، [مجوزها](https://en.m.wikipedia.org/wiki/File-system_permissions)، برچسب‌های زمانی یا سایر فراداده‌ها را رمزگذاری نمی‌کند.

## مثال‌هایی از اشیاء سیستم‌فایل

یک پروندهٔ ساده:

```
50 B, executable: false
```

یک فایل قابل‌اجرا:

```
122 KB, executable: true
```

یک پیوند نمادین (symlink):

```
-> /usr/bin/sh
```

یک پوشه با محتویات زیر:

```
├── bin
│   └── hello: 35 KB, executable: true
└── share
    ├── info
    │   └── hello.info: 36 KB, executable: false
    └── man
        └── man1
            └── hello.1.gz: 790 B, executable: false
```

یک پوشه که حاوی یک پیوند نمادین (symlink) و دیگر پوشه‌ها است:

```
├── bin -> share/go/bin
├── nix-support/
└── share/
```
